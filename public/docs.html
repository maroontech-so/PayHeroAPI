LyCash

A single, secure HTTP API for M-PESA STK Push payments. Integrate once, use across every app, and manage all payments from one dashboard.

Overview

LyCash is a middleware server that sits between your applications and the upstream M-PESA gateway. Instead of embedding gateway credentials in every app you build, you embed LyCash's URL and an API key. This server handles:

  • Secure credential storage (gateway username, password, and channels stay on the server)
  • Per-app API key generation and revocation
  • STK Push initiation to Safaricom M-PESA via the upstream gateway
  • Real-time transaction status polling
  • Webhook receiving and forwarding to your apps
  • Complete audit logging of every request and callback
  • Unified analytics dashboard for all transactions
One API to serve all your apps Build 2 apps or 200 — they all point to the same endpoint with different keys. Add a new app by generating a key, no server changes needed.

LyCash is a payment orchestration API. It uses PayHero as its upstream M-PESA gateway. LyCash is not affiliated with or endorsed by PayHero.

Architecture

Here's how a payment flows through the system:

┌─────────────┐        ┌──────────────────────┐        ┌──────────┐
│  Your App   │──(1)──▶│       LyCash         │──(2)──▶│ Gateway  │
│ (frontend)  │        │  lycash.onrender.com │        │ v2 API   │
└─────────────┘        └──────────────────────┘        └──────────┘
      ▲                        │                             │
      │                        │(3) STK prompt sent          │
      │                        ▼                             ▼
      │                  ┌──────────┐                  ┌──────────┐
      │                  │ Customer │                  │ Safaricom│
      │                  │  Phone   │◀─────────────────│  M-PESA  │
      │                  └──────────┘   PIN prompt     └──────────┘
      │                        │                             │
      │                        │                             │
      │                        │(4) Callback sent ───────────┘
      │                        ▼
      │                  ┌──────────────────────┐
      │◀───(5) poll──────│       LyCash         │
      │                  │  (updates DB)        │
      │                  └──────────────────────┘
  1. Your app calls LyCash with the customer's phone number and amount.
  2. LyCash calls the upstream gateway using its stored credentials and the channel assigned to your API key.
  3. The gateway pushes an STK prompt to the customer's phone via Safaricom M-PESA.
  4. The gateway sends LyCash a callback when the customer enters (or fails to enter) their PIN.
  5. Your app polls LyCash's status endpoint (or receives a webhook) to know the result.

Quick Start

Five minutes from zero to a working STK push:

Step 1 — Get an API key

Log into the admin dashboard with your admin password. Navigate to API Keys, click + New Key, and fill in:

  • Application Name — e.g. "Shop App" (just for your reference)
  • Channel ID — the numeric channel ID from your gateway dashboard
  • Webhook URL (optional) — the URL in your app that should receive payment callbacks

Copy the generated key immediately. It looks like lyc_... and will not be shown again.

Store the key securely Never commit it to git, never embed it in a client-side JavaScript file for public apps, and never email it. Treat it like a password.

Step 2 — Make your first request

Send an STK push with curl:

cURL 
curl -X POST https://payheroapi.onrender.com/api/pay/stk-push \
  -H "Content-Type: application/json" \
  -H "x-api-key: lyc_YOUR_KEY_HERE" \
  -d '{
    "phone_number": "254708765597",
    "amount": 100,
    "external_reference": "order_001"
  }'

If everything is configured correctly, you'll get:

Response — 200 OK 
{
  "success": true,
  "external_reference": "order_001",
  "gateway_response": {
    "success": true,
    "status": "QUEUED",
    "reference": "459f-4830-826e-468950aa6264260747",
    "CheckoutRequestID": "ws_CO_16102026162210086707865597",
    "external_reference": "order_001"
  }
}

An STK prompt will appear on the phone within ~10 seconds.

Step 3 — Poll for status

Poll the status endpoint until you see success or failed:

cURL 
curl -H "x-api-key: lyc_YOUR_KEY_HERE" \
  https://payheroapi.onrender.com/api/pay/status/order_001

When the customer completes payment, you'll see:

Response — 200 OK (success) 
{
  "source": "local",
  "transaction": {
    "external_reference": "order_001",
    "status": "success",
    "mpesa_receipt": "UJGD7B29B0",
    "amount": 100,
    "phone_number": "254708765597",
    "verified_with_payhero": 1
  }
}

Authentication

Every API request must include an x-api-key header containing a valid key from your admin dashboard:

Header 
x-api-key: lyc_a1b2c3d4e5f6...

You can also pass the key as a query string parameter (?api_key=...) for testing, but the header is preferred.

Key properties

PropertyValue
Formatlyc_ + 64 hex characters
Entropy256 bits (cryptographically random)
StorageSHA-256 hashed — plaintext never stored on our servers
ScopeBound to one channel per key
Rate limit100 requests/minute (configurable per key)
RotationRevoke anytime from the dashboard; create a new one
Never expose your key in public code For web apps, always make API calls from your backend. For static sites, use a serverless function as a proxy. If a key is leaked, revoke it immediately from the dashboard.

Payment Flow

The recommended client-side flow for a typical checkout:

  1. User enters phone number and confirms amount on your app.
  2. Your app POSTs to /api/pay/stk-push with the phone, amount, and a unique external_reference.
  3. LyCash forwards the request to the gateway, stores a pending transaction, and returns the gateway's reference IDs.
  4. The gateway sends an STK prompt to the customer's phone.
  5. Your app polls GET /api/pay/status/:reference every 2–3 seconds, up to 2 minutes.
  6. When the customer enters their PIN, the gateway sends a callback to LyCash. LyCash verifies the status, updates the transaction, and — if your key has a webhook URL — forwards a signed POST to your app.
  7. Your app's poll sees success (with M-PESA receipt) or failed (with reason) and shows the result to the user.
Polling vs webhooks Polling is simpler to implement and works everywhere. Webhooks are more efficient for high-volume apps. You can use both: webhooks for server-side order fulfillment, polling for the customer-facing UI.

References & IDs

A single payment has several identifiers. Understanding them prevents most integration bugs.

IdentifierWhere it comes fromBest use
external_referenceYou generate it (must be unique)Idempotency; primary lookup
referenceGateway responseFallback lookup
CheckoutRequestIDGateway response (e.g. ws_CO_...)Fallback lookup
MerchantRequestIDGateway callbackFallback lookup in webhook handler
mpesa_receiptAfter successful payment (e.g. UJGD7B29B0)Customer-facing receipt
You can poll with any of these Our status endpoint matches external_reference, reference, CheckoutRequestID, and mpesa_receipt automatically. Use whichever you have.

Idempotency

The external_reference is unique across all your transactions. If you POST an STK push with a reference that already exists, LyCash returns the original transaction (with idempotent: true) instead of initiating a new charge.

Idempotent response 
{
  "success": true,
  "external_reference": "order_001",
  "idempotent": true,
  "transaction": { ... existing record ... }
}

This means your app can safely retry on network failures. Just use the same external_reference.

Transaction Statuses

StatusMeaningWhat to do
pendingSTK push sent, waiting for customer to enter PINKeep polling
successPayment completed, M-PESA receipt issuedFulfill the order
failedPayment failed — customer cancelled, insufficient funds, timeout, etc.Show reason, allow retry

Error Codes

LyCash returns standard HTTP status codes with JSON error bodies.

HTTPMeaningCommon cause
400Bad RequestMissing field, wrong phone format, invalid amount

When a payment fails, the callback contains a ResultCode from the upstream gateway / Safaricom. The most common ones:

Webhooks (Optional)

If your API key has a webhook URL configured, LyCash forwards every payment outcome to it. This is faster than polling — you get notified the instant the gateway's callback arrives.

Webhook payload

POST to your webhook_url 
{
  "event": "payment.success",
  "external_reference": "order_1792148000",
  "gateway_reference": "459f-4830-826e-468950aa6264260747",
  "mpesa_receipt": "UJGD7B29B0",
  "amount": 100,
  "phone_number": "254708765597",
  "status": "success",
  "verified": true,
  "timestamp": "2026-10-16T13:17:03.449Z"
}

Headers

HeaderValue
X-LyCash-SignatureHMAC-SHA256 of the payload using your webhook secret
X-LyCash-Evente.g. payment.success

Verifying the signature (Node.js)

Express handler 
const crypto = require('crypto');

app.post('/your-webhook', (req, res) => {
  const signature = req.headers['x-lycash-signature'];
  const expected = crypto
    .createHmac('sha256', process.env.WEBHOOK_SECRET)
    .update(JSON.stringify(req.body))
    .digest('hex');

  if (signature !== expected) {
    return res.status(401).send('Invalid signature');
  }

  // Process the payment
  if (req.body.event === 'payment.success') {
    // Fulfill the order
  }

  res.json({ received: true });
});
Always verify signatures Webhook endpoints are public. Anyone can POST to them. Verify the signature before trusting the payload.

Code Examples

Node.js / Express backend

Node.js 
const API_KEY = process.env.LYCASH_API_KEY;
const API_BASE = 'https://payheroapi.onrender.com';

async function initiatePayment(phone, amount, reference) {
  const res = await fetch(`${API_BASE}/api/pay/stk-push`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'x-api-key': API_KEY,
    },
    body: JSON.stringify({
      phone_number: phone,
      amount,
      external_reference: reference,
    }),
  });

  if (!res.ok) {
    const err = await res.json();
    throw new Error(err.message || 'Payment initiation failed');
  }

  return res.json();
}

async function checkStatus(reference) {
  const res = await fetch(`${API_BASE}/api/pay/status/${encodeURIComponent(reference)}`, {
    headers: { 'x-api-key': API_KEY },
  });
  const data = await res.json();
  return data.transaction;
}

Python backend

Python 
import os
import requests

API_KEY = os.environ['LYCASH_API_KEY']
API_BASE = 'https://payheroapi.onrender.com'

def initiate_payment(phone, amount, reference):
    res = requests.post(
        f'{API_BASE}/api/pay/stk-push',
        headers={
            'Content-Type': 'application/json',
            'x-api-key': API_KEY,
        },

            'amount': amount,
            'external_reference': reference,

    res.raise_for_status()

def check_status(reference):

        headers={'x-api-key': API_KEY},
    )
    res.raise_for_status()
    return res.json()['transaction']

PHP backend

PHP 
<?php
$API_KEY = getenv('LYCASH_API_KEY');
$API_BASE = 'https://payheroapi.onrender.com';

function initiatePayment($phone, $amount, $reference) {
    global $API_KEY, $API_BASE;
    $ch = curl_init("$API_BASE/api/pay/stk-push");
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_POST => true,
        CURLOPT_HTTPHEADER => [
            'Content-Type: application/json',
            "x-api-key: $API_KEY",
        ],
        CURLOPT_POSTFIELDS => json_encode([
            'phone_number' => $phone,
            'amount' => $amount,
            'external_reference' => $reference,
        ]),
    ]);
    $response = curl_exec($ch);
    curl_close($ch);
    return json_decode($response, true);
}
?>

async function pay(phone, amount) {
  const reference = 'web_' + Date.now();

  const res = await fetch('https://payheroapi.onrender.com/api/pay/stk-push', {
    method: 'POST',
    headers: {

    }),
  });

  const data = await res.json();
  if (!data.success) {
    alert('Failed to start payment: ' + data.message);
    return;
  }

  const interval = setInterval(async () => {
    const s = await fetch(
      'https://payheroapi.onrender.com/api/pay/status/' + reference,
      { headers: { 'x-api-key': 'lyc_YOUR_KEY_HERE' } }
    ).then(r => r.json());

    const status = s.transaction?.status;
    if (status === 'success') {
      clearInterval(interval);
      alert('Payment received! Receipt: ' + s.transaction.mpesa_receipt);
    } else if (status === 'failed') {
      clearInterval(interval);
      alert('Payment failed. Please try again.');
    }
  }, 3000);

  setTimeout(() => clearInterval(interval), 120000);
}
</script>

Security Best Practices

  • Never expose API keys — Call LyCash from your backend. If you need to call from a browser, use a serverless proxy (Netlify Functions, Cloudflare Workers, Vercel Functions).
  • Use unique external references — Include a timestamp or UUID. This prevents accidental duplicate charges.
  • Verify webhook signatures — Always validate X-LyCash-Signature before trusting a webhook payload.
  • Rotate keys regularly — Create a new key and revoke the old one if a team member leaves or a key is suspect.
  • Bind keys to specific apps — One key per app. If one key leaks, only that app is affected.
  • Monitor your dashboard — Unusual transaction patterns or spikes in 403s indicate a compromised key.

Testing & Debugging

Test phone numbers

Safaricom offers no universal test number, but any Safaricom number with an active M-PESA account works for end-to-end testing. Use KES 1 for cheap tests.

Common issues

SymptomCauseFix
403 Invalid API key Key revoked, mistyped, or cache not refreshed Verify key in dashboard; wait 30s for cache; recreate if needed
STK push returns 200 but no prompt arrives Phone offline, SIM too old, wrong number format Test with a fresh phone; check ResultCode in callback
Callback never arrives Callback URL not registered with the gateway Set it in the gateway's dashboard → Update Account
Status stays "pending" Customer hasn't entered PIN yet, or callback lost Wait 2 minutes; then check the gateway's dashboard directly
ResultCode 1037 Phone unreachable (off, no signal, outdated SIM) Ask customer to check signal or update SIM (*234*6#)

Debugging checklist

  1. Check /health — confirms server and database are up
  2. Check dashboard → Transactions — see every attempt with its status
  3. Check dashboard → Analytics → Recent API Usage — see which endpoints are being hit
  4. Look at your server logs — every callback is logged with the raw payload
